# Dev lessons (self-improving — read before starting)

Maintained by each `/dev-wave` learn step and `/kit-retro`. Newest first. `(n×)` = times observed.
Project-specific lessons go under a `## Project: <name>` heading below the general ones.

## General
- Optional context (a user date format, a locale hint) must never gate the main action: open the panel / run the action first and patch the extra in later; anchor DOM class checks to the element's own child, not any descendant; clean user text before putting it in a query string; verify a setting named in a brief really exists. (2×)
- Undo/revert features: set the terminal state ("undone") only when the revert completes, and restore it on failed/cancelled/expired; never restore from values truncated for display (keep a truncated flag and skip those fields); decide tool access from structured data (e.g. `created=true`), not a regex over step text; consumers import the producer's strict id/filename regex instead of re-writing it.
- Placement bugs (a component mounted inside a layout that hides it) need a committed structural spec that reads the real templates (host exactly once, at top level, not inside a conditional, absent from the toolbar), not only a visibility spec; reviewers flag a one-off check script otherwise.
- The lead appended scope to the wave's contracts file mid-wave with no ping; agents saw it only on their re-read before push. Tell agents when a contract changes (append + a note in the brief they re-read) and reconcile duplicate key specs. Never overwrite a typed user draft, show the server's 400 text, and refresh (not de-dup) a same-key UI item. (2×)
- A dependency missing from the linked node_modules makes every web typecheck show the same "cannot find module" error: treat it as the known baseline (or add the package to the linkFrom tree, see below). lint-staged can rewrite imports on commit: re-run the typecheck after `wt.ps1 commit`. (4×)
- Async init in UI components (await a loader, then create a map/WebGL context and register it in a module-level registry) leaks when the component is destroyed mid-load: add a destroyed guard after every await and unregister on destroy; put it in the brief.
- Sibling MRs for two products both added an unrequested global side effect (a patched browser prototype for screenshots): never patch global prototypes for a nice-to-have; scope it to the component or raise a separate item. State router/preload differences between products in the contract. (2×)
- Cross-repo features: the producer's validation (id regex, which calls bind a tool, header binding, key names) must be quoted verbatim in the consumer brief; nearly every review round found producer/consumer mismatches (e.g. `access.checks` vs `access.permissions`): the producer greps the contract and client code for each key it reads and accepts both while clients vary. The producer agent opens its MR first so the lead can register `track.ps1 -MergeAfter` before the consumers finish. (6×)
- Base-class hooks inherited by 100+ subclasses: tie cleanup to the framework's destroy hook (e.g. Angular `DestroyRef`), not a helper subclasses may skip, and match third-party DOM (overlay containers) by reading the library source.
- Approval/plan expiry must be anchored to the source record's own timestamp, never a first-seen cache marker (an in-memory cache restarts and replays the write); session ownership = exact match, not startsWith; classify 409s by the problem detail. Port a sibling wave's review findings into the next brief. (2×)
- A feature flag whose safety lives in a separately deployed service must ship OFF in production (an empty env default = fail closed) and be enabled once the dependency is confirmed live. One-shot approve/cancel endpoints need ownership + enabled checks, and 404 (gone) vs 409 (already used) need different UI text.
- Secret temp files (bearer tokens) cleaned only in `finally` survive SIGKILL/redeploys: use a dedicated 0700 folder and sweep it by age at startup and before each write.
- `glab api -F file=@<png>` to the uploads endpoint returns 400 on Windows: use `curl.exe --form` with the glab token for MR screenshots. GitLab's /changes API returns an empty diff for large files: reviewers run `git diff <base_sha>..<head_sha>` locally. (5×)
- Briefs must git-grep the target branch before listing work on a second branch (a feature may exist only on one product's branch).
- lint-staged/prettier can re-wrap whole files on every commit (~30 unrelated hunks): say so in the MR body or commit the formatting separately so reviewers see the real change. (2×)
- Expected-error/noise classifiers (for observability or alerting) must match client aborts only at the top level or via named web wrappers; walking the cause chain hides DB/downstream outages. Add negative tests with server-side look-alikes.
- Tightening input validation (strict base64, type allow-lists, size/char caps, content screening) broke working clients: before adding a validator, grep every client caller (mobile apps too) for its real encoding and type labels, apply caps only to inputs the contract names, take limits as per-route parameters, hold the MR until review passes, and key replay/dedupe maps on a digest, not a payload copy. (5×)
- Most review blockers in one wave were agents inventing limits, dropping old filters or guessing endpoints instead of following the cross-repo contract: quote contract limits/error semantics verbatim in the brief, list every contract hook under its owner's items, and make agents find the existing code path a finding names before adding UI. (3×)
- Tests that mock a look-alike exception class (a library one instead of the project's own) or skip headers (CORS lost by a response reset) pass while the real path is dead: throw the exact class the service throws. Registering a job id after putIfAbsent is racy: use an atomic compute. (2×)
- Layout/scroll/max-height fixes escaped QA when verified only at 1920 wide: measure header/panel bottoms and input widths vs innerHeight at 1366x768 AND 1920x1000 with real wheel scrolling only (scrollIntoView hides clipping); CSS-only fixes can be proven before merge by injecting the style on the test environment. (2×)
- Order matters in mappers that build an entity in steps: a flag read from a party in an early setter misses parties resolved later; grep every later setter of that party, add a post-pass and a test of the final entity. (3×)
- Lenient/scoped-input changes (per-type mapper, number normaliser, auto-approve) dropped old accepted inputs (a content type then got 415), glued ambiguous values together, or skipped status/duplicate guards: list every input the old path accepted and test each, plus a re-import test. (4×)
- Review blockers cluster on shared code changed for one path (a shared default, validator, prompt or confirm flow): before changing it, grep every caller and writer, make overrides opt-in, add a round-trip test, and reuse the named shared helper instead of re-implementing its maths. (9×)
- A linked Python `.venv` may lack pytest/ruff/PIL, so the check.ps1 test/lint steps fail there: write validation tests with a `__main__` runner and run them through `gate.ps1 -Cmd`; compile only the changed files when the folder holds unrelated broken scripts. (4×)
- Items that need a product concept get deferred by every agent: collect them into one decisions doc and run a follow-up wave once the owner has decided. (2×)
- `dotnet restore` fails NU1301 when the user's NuGet.Config lists a missing local source: set `RestoreIgnoreFailedSources=true` before check.ps1, and point `-Dir` at the folder holding the .sln. (2×)
- Parallel agents share one scratchpad and overwrite each other's files (e.g. `mr-body.md`): use `scratchpad\<agent-id>\` file names. (2×)
- `devtools.py merge` fails on a GitLab project that was moved to another group: merge with `glab mr merge -R <new group>/<repo>` (kit fix pending: resolve the path from the MR web_url).
- (fixed in kit) Raw tracker-CLI comment/status calls failed for agents, and review status names differ per board ('for review' vs 'in review'), a wrong name failing silently. All tracker calls now go through `tracker.ps1` (or `devtools.py comment|status`) with logical statuses (`review`, `promoted`, `inTest`, `closed`) mapped by `tracker.statuses`; long texts go as a file. Verify posts with `tracker.ps1 comments <id>`. (5×)
- The workflow's computed task can drift from the relayed user request: agents follow the user's request and flag the brief; the coordinator re-dispatches deferred items and keeps request and brief aligned. (4×)
- (fixed in kit) One web repo ships two products from two branches, but wt.ps1 linked node_modules from the main checkout (other branch): agents of the second product typechecked against other-branch installs (18 packages missing) and the gate showed tsc-lint failing every round. wt.ps1 new now picks kit.local.json repos[].linkFromByTarget[<target>] (or linkFrom for the default target). Keep one detached dependency checkout per target branch (git worktree add --detach + frozen-lockfile install).
- (lead fix) A dependency added by a merged MR was missing from the shared linkFrom node_modules, so every later web agent typechecked with a 'declare module' shim and the gate showed tsc-lint failing 3x in a row each round. The lead unpacked the exact pinned version (npm pack + tar into node_modules\<pkg>, no deps) into the linkFrom tree. Lead: after merging an MR that adds a dependency, add it to the linkFrom tree the same way; never run a full install there.
- (fixed in kit) A reviewed MR (paths outside the CI rules -> no MR pipeline) stayed open after its wave: the ship step ran `devtools.py merge` once, got 'WAIT: no pipeline yet (pushed < 5 min ago)' and never retried. auto_merge now waits out the 5 minutes itself and merges (or schedules merge-when-green if a pipeline appeared).
- (fixed in kit) GitLab drops "merge when pipeline succeeds" when new commits are pushed after scheduling (an agent rebased and force-pushed after `devtools.py merge`; the MR then sat open with a green pipeline while the agent reported "scheduled"). devtools.py merge now records the intent in <runtime>/automerge.json and `track.ps1 run` (every supervise round) re-arms it until the MR merges or closes.
- (fixed in kit) Merging main into a staging branch that got main earlier through a squashed merge gives add/add conflicts on every file that changed since. If the staging copy is byte-identical to an older main version of the file, main's current version is always right. deploy-merge.ps1 applies that rule, compiles, and pushes a plain fast-forward; any other conflict stops it.
- A Spring bean given a second (package-private, test-only) constructor without `@Autowired` on the real one built and passed unit tests but crashed app startup ("No default constructor found") and failed the deploy. When a bean has 2+ constructors, mark the injected one `@Autowired`; unit tests that call constructors directly never catch it.
- (fixed in kit) A repo with no MR CI (deploy-only pipelines) never gets an MR pipeline, so `devtools.py merge` set merge-when-pipeline-succeeds and the MR waited forever. merge/merge_when_green now merge directly when the MR has no pipeline and its head commit is > 5 min old (younger: returns WAIT, run again).
- (fixed in kit) guard.ps1 blocked a read-only `Get-Process java,node,msbuild` as an ungated heavy build: `msbuild\b` matched the word anywhere. msbuild now counts only when it is run as a command (start of a segment, after & ; | ( or a quote).
- (fixed in kit) .NET checks never ran through check.ps1: stack.ps1's dotnet commands use a `{sln}` placeholder that check.ps1 never filled ("MSB1009: Project file does not exist. Switch: {sln}"). check.ps1 now fills it with the .sln in the stack dir, else its single project file.
- A squash merge makes an agent's own commits look "not in main" (`merge-base --is-ancestor` is false) even when their content is. Compare trees (`git diff <branch> origin/main -- <path>`), not commit ancestry, before assuming a fix round didn't land.
- (fixed in kit) A Liquibase changeSet commented 'not reversible' with an EMPTY `<rollback/>` failed the CI changelog check: lbcheck.py now flags missing or empty rollbacks on changeSets marked irreversible. Agents stopped at 'MR opened' and nobody saw failed pipelines: dev-wave now waits for MR pipelines (pipe-wait.ps1, cheap 'ci' step) and sends failures to the fix round.
- A new helper/member inserted between an existing Javadoc/JSDoc and its method steals the doc comment (review nits in Java and TS): add new members above the doc block or below the method. (2×)
- `track.ps1 add -Discover` can find no MRs right after `devtools.py mr` (search lag): pass `-Mrs <repo>!<iid>` explicitly as well. (4×)
- A client flag like "already on server" must not trust the 200 of a queueing endpoint (it only stores the request for later processing): fix it server side (fall back to the latest earlier request for the same id) and test the failed-then-resubmitted case. (2×)
- A local-DB schema bump or a new sync-derived field in a mobile app needs a forced full sync on upgrade (migration + wipe fallback reset the sync cursor), else the delta sync never backfills records already on the phone; verify by upgrading in place over an old APK. (2×)
- Feature/isolation gates (hide new behaviour where it is off): gate only what the new feature introduced (not older security checks), grep every consumer of a gated API or seeded row (a role hidden in one list but not in other filters), give each gate on and off tests, and set remembered flags on every known session, not only a fresh sign-in. (4× review findings)
- A global style rule with `!important` can beat a component library's variant (e.g. danger buttons): fix a feature's dialogs in the component's own, more specific style. A crash seen on one screen can come from a shared component: trace the stack first.
- Swapping a shared helper into a module can change behaviour the brief says to keep: diff outputs for edge cases (zero sizes, special units) or get a product decision.
- The guard can false-positive on PowerShell commands whose text holds slash paths or arrows; put such text in a script file via the Write tool and run that. Use the Edit tool, not sed/python/heredoc, for CRLF files and anything with backslashes.
- A web app with no unit-test target makes the `check.ps1` test step fail: keep logic in exported pure functions; specs are type-checked, or bundled with esbuild (through gate.ps1) and run under node with a tiny shim. (5×)
- `board.ps1 check` prints ok but can leave `$LASTEXITCODE` null/stale, so `-ne 0` guards falsely stop: test its output text or `-gt 0`. (4×)
- Git Bash `python`/`py` can be a broken pyenv .bat shim (`python -c` multi-line fails; emoji hit cp1252): write a .py file in the scratchpad, run it from PowerShell with PYTHONIOENCODING=utf-8, or use `node -e`. `python -I` ignores PYTHONIOENCODING: use `-X utf8` or reconfigure stdout. (36×; reviewers hit it on every MR JSON dump)
- (fixed in kit) `wt.ps1 commit` stages everything (`git add -A`) unless `-NoStage`. (3×)
- `devtools.py merge-wait` needs a background timeout of 3600000 and a log file (10 min kills it mid-pipeline); prefer `devtools.py merge` (schedules and returns). `devtools.py doc` handles absolute paths itself (fixed in kit). (2× each)
- Duplicate dev agents (SendMessage to a workflow agent's ID spawns a copy) share one worktree and interleave edits; relay via contracts.md. Husky v8 `core.hooksPath=.husky/_` skips hooks (wt.ps1 falls back to .husky). (3×; commits made with skipped hooks can fail CI init: recommit)
- Heap caps are dynamic and learned PER PROJECT (main repo + subproject folder, e.g. `backend/services/api`; worktrees share their main repo's profile): a new project starts at Gradle 12 / Maven 8 / Node 4 GB, then learned peak × 1.25 (never below 4 GB, never above the start), shrunk toward 4 GB when memory is tight. JVMs run G1 with tight free-ratios so the learned peak can fall. Inherited -Xmx (e.g. a user `MAVEN_OPTS=-Xmx16g`, which once made one `mvn test` take 6 GB) is always overridden.
- Claude Code sets `NoDefaultCurrentDirectoryInExePath=1`: bare `gradlew.bat` / `mvnw.cmd` aren't found in the current dir. Use `.\gradlew.bat` (the gate and stack.ps1 add `.\` automatically).
- `check.ps1` typecheck is incremental (cache in `.claude-runtime\tsbuild`): 16 s → 6 s on a large Angular app. Don't pass your own `--incremental`.
- The memory gate learns real peaks per build kind (`%TEMP%\claude-build-gate\history.json`); long waits print the biggest memory users — if an IDE or another session hogs RAM, say so instead of retrying.
- Six parallel Maven JVMs hit 100% RAM; every build goes through the gate (the guard hook blocks ungated builds).
- Worktree hooks were silently skipped (`core.hooksPath` missing in worktrees) → always `wt.ps1 commit`.
- One agent popped another's `git stash` → stash is blocked by the guard; use WIP commits.
- A hook/side effect added after a service call must check the call really took effect (a cancel method that silently returns for an already-paid record once caused double billing): reload state, test the status, add a test for the no-op branch.
- Agents can report before the API pipeline finishes; web MRs must merge after their API MR: the coordinator confirms the merge before QA, and consumers are registered with `track.ps1 add -MergeAfter '<web>!<iid>><api>!<iid>'`. (6×)
- Forms that rebuild a payload from visible fields wipe stored values on update: prefill from the existing record and send unchanged values back; the API must not clear fields that are absent. Skip idempotent syncs when the request equals stored values. (3×)
- When widening a status filter or adding report columns, keep old exclusions and update every report definition sharing the summary. (2×)
- Signed numeric inputs need a signed keyboard on React Native (`decimal-pad` has no minus key); test typed input, not just a set value.
- A main checkout on another branch links the wrong `node_modules` versions into a worktree: `wt.ps1 new ... -LinkFrom <a checkout of the target branch>`.
- Merge API MRs first, then web/app; test-environment deploys lag — call stale deploys out instead of "fixing" them.
- A shared multi-environment service (one function serving staging + production): put the environment in tenant identity (DB name, cache key, key-to-server map), never accept a key whose secret is committed, make external calls after commit on a bounded executor with a cooldown, and put new per-item calls inside the item's try. Read-only views too: bound wall-clock (small pool + deadline, return `pending`, the client re-asks) and classify errors so a view never trips a back-off shared with billing. (2×)
- Shared formatters/styles must not be fixed globally for one entity (labels of one entity leaked into another; a global ellipsis broke headers): key by field/selector and test each other consumer. (2×)
- Never block app startup/resume on a network call without a connectivity check and a short timeout: offline goes straight to stored data and the fetch fires unawaited.
- Role/web fixes cannot be live-tested before merge when the test site serves an older build: record a post-deploy live check instead of blocking review on it. (3×)
- Fixes keep covering one path only (single GET but not the list, one error branch but not the other, import but not the edit round-trip, a side effect called in two branches): test sibling endpoints and the full round-trip, and grep the flow for an existing call before adding a side effect. (4×)
- Data-fix migrations need a backup table (old + new values, INSERT..SELECT, UPDATE through it) with a restoring rollback; a derived field must reuse the rule existing consumers use (grep for it first). (2×)
- A new server 4xx refusal on a mobile action needs a guard narrow enough to hit only the intended state and an app end state (refused drafts block logout as unsent work); if the error type drops its key, re-read server state to detect it. Ship the API first.
- Copy/split of a record that carries rates, extras and lines: re-rate the original, strip per-record charges from the copies, guard against already-invoiced/dispatched records, add a sum-of-rates test.
- Existing migration stubs may already create a column/table: never add what is there; `check.ps1 -Step migrations` must print `ISSUES 0`.
