# Dev lessons — active rules (read before starting; ≤ 40 lines)
Newest first, one line each, `(n×)` = times seen. Fixed/old entries live in `HISTORY.md` (never read it for work).
Project-specific lessons go under `## Project: <name>` below the general ones.

## General
- Optional context (a date format, a locale hint) never gates the main action: run it first, patch the extra in later; anchor DOM class checks to the element's own child; clean user text before querying; verify a setting named in the brief exists. (2×)
- Undo/revert and expiry: set the terminal state only when the revert completes (restore it on failed/cancelled/expired); never restore display-truncated values; decide access from structured data, not regex over text; anchor expiry to the source record's timestamp, not a first-seen cache marker; ownership = exact match; classify 409s by problem detail. (3×)
- UI lifecycle: placement bugs need a committed structural spec over the real templates (host once, top level, not inside a conditional); async init (await, then map/WebGL + global registry) needs a destroyed guard after every await and unregister on destroy; tie base-class cleanup to the framework destroy hook (e.g. `DestroyRef`); never patch global prototypes for a nice-to-have. (3×)
- Re-read `<brief>.contracts.md` before every push (the lead appends scope mid-wave); never overwrite a typed user draft, show the server's 400 text, refresh (not de-dup) a same-key UI item. (2×)
- Cross-repo contracts: quote the producer's validation (id regex, key names, limits, error semantics) verbatim; the producer greps contract + clients for each key it reads and accepts both spellings while clients vary, and opens its MR first; never invent limits, drop old filters or guess endpoints; find the existing code path a finding names before adding UI. (9×)
- Shared code changed for one path (a default, validator, prompt, confirm flow, helper, formatter, global style): grep every caller, writer and consumer first, make overrides opt-in, add a round-trip test, reuse the named shared helper; key shared formatters/styles by field/selector; `!important` globals beat component variants (fix in the component's own style); trace a crash's stack (shared component?) first. (12×)
- Fixes that cover one path only keep coming back: test sibling endpoints (single GET and list), every error branch, the full round-trip (create/import, edit, cancel on approved/invoiced states); for lenient/scoped inputs list every input the old path accepted and test each, keep status/duplicate guards. (8×)
- Before tightening validation (strict base64, allow-lists, size/char caps, screening) grep every client caller (mobile too) for its real encoding and labels; cap only inputs the contract names, per-route limits; key replay/dedupe maps on a digest. (5×)
- Forms that rebuild a payload from visible fields wipe stored values: prefill from the record and send unchanged values; the API never clears absent fields; skip idempotent syncs. Widening a status filter/report keeps old exclusions and updates every report sharing the summary. (5×)
- Side effects after a service call: reload and check it really took effect (a silent no-op cancel once double-billed); grep the flow for an existing call before adding one; test the no-op branch. A queueing endpoint's 200 is not "already on server": fix server side, test failed-then-resubmitted. (3×)
- Mappers that build an entity in steps: a flag read from a party early misses parties resolved later; grep every later setter, add a post-pass and a final-entity test. (3×)
- Feature/isolation gates: gate only what the feature introduced, grep every consumer of a gated API or seeded row, on and off tests, set remembered flags on every known session. (4×)
- Flags whose safety lives in a separately deployed service ship OFF in production (empty env = fail closed); one-shot approve/cancel endpoints need ownership + enabled checks; 404 (gone) vs 409 (used) get different UI text.
- Shared multi-environment services: the environment is part of tenant identity (DB name, cache key, key map); never accept a key whose secret is committed; external calls after commit on a bounded executor with cooldown, per-item calls inside the item's try; read-only views get a wall-clock bound and classified errors; secret temp files live in a 0700 folder swept by age (`finally` misses SIGKILL). (2×)
- Noise/expected-error classifiers match client aborts only at the top level or via named web wrappers (walking the cause chain hides outages); add negative tests with server-side look-alikes.
- Data-fix migrations: backup table (old + new values) with a restoring rollback; a derived field reuses the rule existing consumers use. Copy/split of a priced record: re-rate the original, strip per-record charges from copies, guard invoiced/dispatched, sum-of-rates test. (2×)
- Mobile: a local-DB schema bump or new sync-derived field forces a full sync on upgrade (verify by upgrading over an old APK); never block startup/resume on the network without a connectivity check and short timeout; signed numbers need a signed keyboard (`decimal-pad` has no minus); a new server 4xx on a mobile action needs a narrow guard + app end state, API ships first. (4×)
- Tests: throw the exact exception class the service throws, keep headers (CORS); register job ids atomically (compute, not putIfAbsent + put); a Spring bean with 2+ constructors needs `@Autowired` on the injected one (unit tests miss the startup crash). (3×)
- No unit-test target (web): keep logic in exported pure functions; type-check specs or bundle with esbuild through `gate.ps1` and run under node. A linked `.venv` may lack pytest/ruff/PIL: `__main__` runner through `gate.ps1 -Cmd`; compile only changed files when the folder holds broken scripts. (9×)
- A package missing from the linked `node_modules` gives every web typecheck the same "cannot find module": treat it as the baseline and say so; lint-staged can rewrite imports and re-wrap whole files on commit: re-run the typecheck after `wt.ps1 commit`, mention reformatting in the MR body. (6×)
- Layout/scroll/max-height fixes: measure at 1366x768 AND 1920x1000 with real wheel scrolling (scrollIntoView hides clipping); CSS fixes can be proven pre-merge by injecting the style on the test environment. (2×)
- Role/web fixes on a test site serving an older build: record a post-deploy live check instead of blocking review. Squash merges hide your commits from ancestry: compare trees (`git diff <branch> origin/main -- <path>`). (3×)
- New members go above an existing doc comment or below its method, never between them. (2×)
- Git host: `glab api -F file=@<png>` returns 400 on Windows (use `curl.exe --form` with the glab token); /changes is empty for large files (reviewers `git diff <base_sha>..<head_sha>`); a project moved to another group needs `glab mr merge -R <group>/<repo>`; prefer `devtools.py merge` (schedules, returns) over `merge-wait`; `track.ps1 add -Discover` lags: also pass `-Mrs <repo>!<iid>`. (11×)
- `dotnet restore` NU1301 (a missing local NuGet source): `RestoreIgnoreFailedSources=true`; point `-Dir` at the folder holding the .sln. (2×)
- Shell: Git Bash `python` can be a broken shim (write a .py file, run it from PowerShell with PYTHONIOENCODING=utf-8 or `-X utf8`; `-I` ignores the env var; or `node -e`); the guard can false-positive on commands with slash paths, arrows or escaped quotes (put the text in a script file); use Edit, not sed/heredoc, for CRLF files and backslashes; `board.ps1 check` can leave `$LASTEXITCODE` stale (test its output text). (40×)
- Parallel agents share one scratchpad: use `scratchpad/<agent-id>/` file names. Items that need a product decision: defer with a reason. (4×)
