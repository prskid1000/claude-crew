# duel

Stale, optional (since 2026-11-14): the core /buildy has the review rebuttal (devy `disputes`, revy answers once, a split goes to the owner) and a trigger-based written debate (`rechy` kind debate, `bossy.ps1 debate`); use those first. This goody stays only for a big fork where two builds are worth paying for.
`workflows/buildy-duel.js`: /buildy as of 2026-10-21 (behind the core since) with `mode: 'duel'`: two devy POCs of one question, revy compares, a debate (max 3 rounds), the owner judges (`decide ask`), the winner ships through the dev flow. `bossy.ps1 board dispute | disputes`: an agent disagrees with another's result outside a /buildy fix round; the other answers once with evidence; still split after 2 rounds, or silent 2 h, -> a `decide ask` the owner judges (bossy E4, DECISION).
Needed when: the owner wants two approaches built and compared before one ships (a design question alone: the core debate).
Wiring: a standalone workflow, `Workflow({ scriptPath: "<kit>/workflows/buildy-duel.js", args })`: /buildy args plus `mode: 'duel'`, `duel: { question, approaches?, rounds }`, exactly 2 agents; the debate record (shape: `skills/crafty/templates-debate.md`) goes to `<runtime>/work/duels/<run>.md`. `skills/bossy/adapters/board_disputes.ps1`, dot-sourced by bossy.ps1; supervise -AutoFix calls its `Get-KitSuperviseFlagsDisputes` (2 h expiry); runtime path `disputes`; the dispute text: `skills/crafty/templates-dispute.md`. Tests: `tests.ps1` (runs `tests-*.ps1` too).
