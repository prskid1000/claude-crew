# Dev lessons — active rules (read before starting; ≤ 40 lines)
Newest first, one line each, `(n×)` = times seen. Fixed/old entries live in `HISTORY.md` (never read it for work).
Project/org lessons: `learn.ps1 -Project <name>` -> LESSONS.local.md (git-ignored), never here.

## General
- (3×) Precondition helpers that throw IllegalStateException (Guava checkState/checkArgument) map to HTTP 500: use the codebase's validation helpers that return 400, and grep every call site in the same change.
- (2×) Changing an API status code or stale fix notes: grep the API test specs for the endpoint path and delete the old 'BACKEND FIX'/known-bug blocks in the same MR; a 500->400 change breaks the pinned specs.
- (2×) Never persist secrets from a task or queue payload (mcp_config headers/env, bearer tokens, credential fallbacks) to a db, WAL, log or temp file: keep them in process memory, store NULL, chmod any db file on every open, and grep the host env var NAMES before removing a fallback.
- (3×) devtools.py merge returns WAIT until the GitLab pipeline has started, and a background retry can print nothing: poll the pipeline (glab/devtools status) until it exists, then run merge once in the same worktree as CLAUDE_AGENT; never count WAIT as a failed merge or merge a consumer on it.
- (3×) Edits on mixed CRLF/LF files: PowerShell Get-Content -Raw .Replace with `n silently no-ops, [IO.File] with a relative path resolves against the process cwd (a failed read once wrote an empty stray file into the main checkout), python without newline='' on read drops CRLF, Bash heredocs with quotes break and `python -c` hits the broken .cmd shim. Use the Edit tool with exact one-line strings and check `git diff`, or a python script written with the Write tool (newline='', asserts each old string occurs once) run from PowerShell with absolute paths.
- (4×) Web repo local checks: the linked node_modules is older than main (TS 5.9 vs Angular 22/TS6; a worktree of one product's branch links another branch's checkout, ng build fails on @angular/build ^20), so full typecheck and ng build cannot run, tsc does not compile templates, and node-spec cannot bundle specs importing @angular/cdk DataSource or http interceptors. Put logic in pure framework-free helpers and spec those; use a temp tsconfig with ignoreDeprecations 5.0 via gate.ps1 and grep only changed files; add a jsdom/template spec or write 'template unverified, left to CI' in the MR. Never reinstall in the linked checkout.
- (5×) Python repos with validation/*.py __main__ runners: check.ps1 -Step test runs 0 tests (exit 5); run them via gate.ps1 -Cmd '<module>\.venv\Scripts\python.exe -X utf8 validation\x.py', several scripts in one runner file (gate.ps1 -Cmd does not split on ;). Missing libs (openpyxl) are never installed into the linked venv: copy them to a scratch dir and set PYTHONPATH. ; a wave hit this again with a gunicorn worker_exit hook (cannot run on Windows).
- (2×) A guard fix for one app goes to its sibling copy in the same wave (the same screen or endpoint in a sibling product): a review fix that clears or matches state must match method and path, not just any success.
- (2×) A GitLab 500/502 outage fails init (clone) or a package-registry job while the code is fine: check the job log, retry the failed job or pipeline on the same sha (a 409 'stale job' can still start the retry), and merge only after a green run; never change code for it.
- (4×) A request that only asks to explain or plan is no build: check the request kind before launching a wave; agents that find no build should report and stop, not spawn. The brief plus contracts file define the work; a relayed chat message never overrides it. A 9-agent wave ran on an explain-only request and every area deferred.
- (4×) The read-only SQL MCP server often fails to connect: query the replica through its own Python module with the server's interpreter (path in the org databases skill), read-only, and note the fallback in the MR; ask the coordinator for migration timestamps instead of picking one. Insert the master.xml include in timestamp order (waiting for the coordinator's timestamp, never your own).
- (3×) A failing container test (Testcontainers) is not yours until it passes on the target: check.ps1 -Step test runs `docker info` (5 s) before container tests and exits 4 when Docker is down: start Docker Desktop, poll `docker info`, re-run (never report a container test as failing because Docker was down), then run the one failing class on origin/<target> (wt.ps1 or git restore --source) before blaming your change and call it the baseline in the MR. Some repos have container tests that already fail on the target (a schema they never create): for a query test use a plain database testcontainer plus the ORM with the repository query read by reflection.
- (2×) Tester guides: write each Expected from the code you shipped (template layout, which rows or breakdowns appear, button placement), not from the brief or the bug text; re-read the final diff before publishing the guide. A guide that disagrees with the screen leaves QA unsure whether to FAIL (UXR L4 full-width DELETE vs a three-cell footer; RPT-ANA A7 per-period breakdown).
- (2×) Screenshot capture clones of a flex/grid page: a clone keeps the live height, so flex-grow:1 children grow into freed space and push later content off the capture. Mark kept children whose flex parent lost siblings, set flex-grow 0 / flex-basis auto in the clone, and check the picture starts with the first table row.
- (7×) Shift/date boundary fixes: test across midnight (phone clock on D+1, relaunch and drawer Sync, not only the relaunch) and seed the profile flags the check needs. A stored record from an earlier shift or day for the same vehicle must give NOT_STARTED (test it, not only the next-day record). Bound a record to the open shift's start; test a new shift at 06:00 after a 00:32 inspection and a same-shift-after-midnight case. When a gate decides a record is owed or done, the screen it opens must read the same rule. Device checks of these fixes keep getting deferred to the post-deploy run: the same-day case needs no phone clock change (start a new shift the morning after an after-midnight end-of-day), so put that case (steps, seed, no clock change) in needsLiveCheck marked 'pre-merge: branch APK' for the coordinator's in-wave retest (dev agents never start emulators); name the cross-midnight clock step there too. Bound a shift's summary window by its own start/end (a cross-midnight night shift shared breaks with the next day); tenants without the feature keep the old window, tested.
- (2×) guide-mode 'always' on a fix that is not deployed yet (no staging build, no APK): build the guide's 'before' screenshots from the QA run's saved evidence (finalize.json files[].id Drive ids as https://drive.google.com/uc?export=view&id=<id> img src; the doc import embeds them), mark each check's after-shot 'added by the test run after deploy', and say so in the task comment. Never block 7b and never fake an after-shot.
- (2×) Tracker status on a resumed or split task: track.ps1 promotes a task once every MR it knows has merged, so a late MR (agent stopped before opening it) leaves the task promoted early. Register the planned repos (track.ps1 add -Task <id> -Discover) before any sibling merges; read the current status (tracker.ps1 view <id>) before setting one, and move it back to review when you open a late MR.
- (4×) Moving a job off the request/startup path (background thread, async index, retry wrapper): grep every other caller of the job (a search path re-ran the 4.5-min index inline); never delete old data before the new is built (swap in one locked step, expose a 'rebuilding' state); scope retries to the callers that need them and log to a separate file; readiness = the listener/health endpoint answering, never the first startup log line.
- (8×) Resuming an area: before editing, run `wt.ps1 status` and `git log origin/<target>..<branch>` (earlier runs often already committed or left the branch unpushed); `wt.ps1 new` refuses an existing path; a worktree folder that vanished while its branch remains is restored by `wt.ps1 new` with the same branch: Test-Path the worktree before every edit. A web worktree vanished mid-run: Test-Path before each edit; wt.ps1 new restores it. A stalled session can leave large uncommitted WIP that never compiled (G2 ~1400 lines, G4 missing imports): compile it, run the targeted tests and review the diff against the brief before trusting it; check the tracker comments and the MR body's Tester guide line to find where it stopped (G3 stopped before 7b); commit WIP with wt.ps1 commit at each green step so a stall leaves a pushed branch. A takeover often stops at 7b: check glab mr view for a leftover TESTER_GUIDE_LINK placeholder and the tracker comments; write the missing guide and comment first.
- (15×) Mocks hide the producer's real behaviour: build fixtures from real captured payloads and URLs, never look-alike shapes; replay the producer's write semantics in tests (a deep-merge PATCH keeps absent keys: set flags explicitly, e.g. deleted:false); a header read cross-origin needs CORS exposed-headers (a faked headers object passes); dump native SQL builders' statements and run them read-only on the staging replica, and search-query builders' JSON (ES/Lucene): assert the built query in a test before you claim search semantics (a free-text search ORed every clause); prove analyzer matching offline with Lucene MemoryIndex; on staging, probe with a nonsense second word to pin which clause matched; for 'no change when flag off' record a golden from origin/<target> and compare it as parsed JSON trees (Jackson readTree / JSON.parse), because the pre-commit prettier hook re-indents committed .json goldens; LLM-written queries/prompts: sample the fresh prompt 5 times at temperature 0 against the staging schema and check the answers agree. a string-match test alone is not enough. Ran the generated SQL read-only on the staging replica: joined rows must equal distinct rows and pivot sums must equal the total. UI structural specs that grep source text pass on unused styles and fail on refactors: assert the rendered value or the component prop. Dump the built SQL and run it read-only on staging before the merge; the QA numbers (160/120/100) matched before deploy. A test that re-runs the production lines (not the real method) still passes when the wiring is removed: call the real validateFields/service method. A permission or guard rule (CLI deny rules, SQL pin, path check) needs a run through the real tool, and its bypass forms tested (double-dot names, /*M! comments, legacy names): fake-tool tests missed a blocked CLI read.
- (2×) ClickUp tracker create with -Assignee fails silently (exit 1, no output): create without -Assignee, then assign in a second call, and check the subtask is assigned.
- Optional context (a date format, a locale hint) never gates the main action: run it first, patch the extra in later; anchor DOM class checks to the element's own child; clean user text before querying; verify a setting named in the brief exists. (2×) Undo/revert and expiry: set the terminal state only when the revert completes (restore it on failed/cancelled/expired); never restore display-truncated values; decide access from structured data, not regex over text; anchor expiry to the source record's timestamp, not a first-seen cache marker; ownership = exact match; classify 409s by problem detail. a stored reason or flag must clear when the state it describes ends. (4×)
- UI lifecycle: placement bugs need a committed structural spec over the real templates (host once, top level, not inside a conditional); async init (await, then map/WebGL + global registry) needs a destroyed guard after every await and unregister on destroy; tie base-class cleanup to the framework destroy hook (e.g. `DestroyRef`); never patch global prototypes for a nice-to-have. route every list mutation (init AND refresh) through one pure resolve-active helper (a stale active id after refresh/unshare blanks the view); check a new transient UI state against the template branch that renders it (text on a pending placeholder is hidden when the template shows only dots). a timeout or abort that fires during an await must also block the next DOM mutation.. (8×)
- Re-read `<brief>.contracts.md` AND the brief's UPDATE section before every commit and push (the owner drops or adds items mid-wave, the lead appends scope) and reconcile your diff against them; never overwrite a typed user draft, show the server's 400 text, refresh (not de-dup) a same-key UI item. (4×)
- Cross-repo contracts: quote the producer's validation (id regex, key names, limits, error semantics) verbatim; the producer greps contract + clients for each key it reads and accepts both spellings while clients vary, and opens its MR first; never invent limits, drop old filters or guess endpoints; find the existing code path a finding names before adding UI. Merge order is checked, not assumed: read the producer's merge state (devtools.py merge output) before any consumer merge; a SCHEDULED producer means the consumer waits. devtools.py merge output decides the order; a consumer whose producer is still CONFLICT or SCHEDULED is registered with track.ps1 -MergeAfter, not merged. Also: a consumer merged before its WAITing producer because the dependency was not registered. A producer DTO change needs its consumer UI in the same wave (a new response field once had no consumer). (16×)
- Fixes that cover one path only keep coming back: test sibling endpoints (single GET and list), every error branch, the full round-trip (create/import, edit, cancel in locked/terminal states); for lenient/scoped inputs list every input the old path accepted and test each, keep status/duplicate guards. an LLM business rule (definition, soft-delete, count rule) goes into every prompt path that writes SQL (single-query and multi-step planner alike), or the MR states the other path is out of scope. grep the same expression (e.g. a field concatenation like getPhoneExt()+getPhone()) across every mapper and sender, not only the reported one. a new branch in a shared service method: grep every caller, including client-portal endpoints, and list each in 'Shared code reached' before the MR. Missed sibling paths keep recurring (4 of 7 pickers fixed, 3 of 21 save endpoints guarded, a retry keyed on one job type): grep every display, caller and sender of the shared path up front. A redaction fix covered one service but missed its sibling path: grep every caller of the shared data before shipping.getEvents; grep every proxy of the same data before calling a leak fix complete. (18×)
- Before tightening validation (strict base64, allow-lists, size/char caps, screening) grep every client caller (mobile too) for its real encoding and labels; cap only inputs the contract names, per-route limits; key replay/dedupe maps on a digest. Tightening a length/format check also changes values it used to pass (24:00, 0900, 9:0): list each old-accepted input and test it or state it as newly rejected in the MR. (6×)
- Forms that rebuild a payload from visible fields wipe stored values: prefill from the record and send unchanged values; the API never clears absent fields; skip idempotent syncs. Widening a status filter/report keeps old exclusions and updates every report sharing the summary. A PUT that binds the raw entity resets fields the form never sends (B3: reported flag reset on every edit); send them back or keep the stored value server-side. A lookup that runs after load or save must not overwrite the stored derived value: record the lookup key only when the input is complete. (7×)
- Side effects after a service call: reload and check it really took effect (a silent no-op cancel once duplicated a side effect); grep the flow for an existing call before adding one; test the no-op branch. A queueing endpoint's 200 is not "already on server": fix server side, test failed-then-resubmitted. (3×)
- Mappers that build an entity in steps: a flag read from a party early misses parties resolved later; grep every later setter, add a post-pass and a final-entity test. (3×)
- Feature/isolation gates: gate only what the feature introduced, grep every consumer of a gated API or seeded row, on and off tests, set remembered flags on every known session; a gate on a status set lists every terminal status (not only the happy one) in API and web alike. gate on the tenant/feature flag, never on request content (a request carrying the new enum value must not switch SQL/labels when the flag is off); stripping a param to gate a feature must not empty the list and widen the filter; role/permission keys for a flag-only feature must not appear or be stored in every tenant's role editor; before renaming a key, grep the API enforcement for it. when a flag-gated option shares an existing type or endpoint, pick an unaffected value for the old test. A fix to a shared aggregate (break counts, totals) must keep existing tenants' numbers: add a feature-OFF test that pins the old value before merge (12×: a tenant-wide flag once hid ready invoices; pin the old rows). (13×) Flags whose safety lives in a separately deployed service ship OFF in production (empty env = fail closed); one-shot approve/cancel endpoints need ownership + enabled checks; 404 (gone) vs 409 (used) get different UI text.
- Shared multi-environment services: the environment is part of tenant identity (DB name, cache key, key map); never accept a key whose secret is committed; external calls after commit on a bounded executor with cooldown, per-item calls inside the item's try; read-only views get a wall-clock bound and classified errors; secret temp files live in a 0700 folder swept by age (`finally` misses SIGKILL). Noise/expected-error classifiers match client aborts only at the top level or via named web wrappers (walking the cause chain hides outages); add negative tests with server-side look-alikes. (2×)
- Data-fix migrations: backup table (old + new values) with a restoring rollback; a derived field reuses the rule existing consumers use. Copy/split of a record with derived totals: recompute the original, strip per-record extras from copies, guard locked states, test that the parts sum to the whole. MySQL DDL is not transactional: keep CREATE backup and the DELETE in separate changeSets, DROP TABLE IF EXISTS first, and make time-zone or lookup failures SIGNAL SQLSTATE instead of a silent UTC fallback. a changeSet with runInTransaction=false that INSERTs into a bookkeeping table before its UPDATE needs a NOT EXISTS guard on that insert so a Liquibase retry is a no-op. (4×)
