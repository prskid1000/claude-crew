**Load when** (all must hold): you are the main session; the router matched a coordinator, dev-flow, test-only, deploy or kit
row.
**Not when:** you are `devy` -> `dev-kit`; `checky` -> `qa-kit`; `revy` / `kitty` -> their agent steps; one small change ->
`dev-kit`.
**Hands off to:** `/buildy` (spawns `devy` + `revy`), `/testy` (spawns `checky` lead / test / verify), `/tidy`
(`kitty`), one `kitty` (kit changes, audits, ENV-FIX), the owner (decisions, disputes, duel verdicts).
**Files** (read or run each only at its step or event row):

## One orchestration model (both flows)
State every run shares: launch record (`orch.ps1 launch`), agent board (`board`), tracking (`.state/tracking.json`, `track`),
decisions (`decide`), contracts (`<brief>.contracts.md` or `<runDir>/lead-notes.md`), the run report (`report -Run <id>`). Both
workflows return `{ agents|results, deployBatch?, decisions?, retroDue }`; they differ only in their steps. Launch by path:
`Workflow({ scriptPath: "<kit>/workflows/<wf>.js", args })`, always with `kitDir` (absolute) and `mandate` (the owner's words).

**Dev flow** (/buildy = `devy` -> `revy` -> CI -> merge -> `devy` (doc, tracker), or one `devy`, or you on a small change;
steps: AGENTS.md "The two flows"): merged work waits silently (`deploy request`) until a person says `deploy <env>` -> E5.

| Dev path | Who / what | You do |
|---|---|---|
| success | build -> local PASS -> review clean -> CI green -> merged | nothing; E7 at the end |
| local test failed | the agent loops (fix, redeploy, all goals) up to 3 rounds, `localRetries` more, then ONE stronger round (`models.retest`) | nothing; it reports `localTest` |
| still FAIL after the stronger round | MRs stay open, item held with the failing goals | you decide: a follow-up wave, or ask the owner |
| ENV-FIX (local env) | the agent stopped one item for a coordinator-only env fix (`needsEnvFix`); BLOCKED only = owner decision / remote-only | E4 |
| needs decision | the agent stopped one item (`decide ask`), others continue | E4: relay, `decide answer`; the workflow resumes it |
| review findings / CI red | one fix round (local tests again), CI again | nothing; open findings -> follow-up wave |
| conflict at merge | append-only: auto (keepboth); real code: blocking finding | follow-up fix (E7) |
| infra flake | the step retries once | a second failure -> E2 |
| held repo (`holdMerge`) | MR open, reviewed, green | the owner's yes, then `devtools.py merge` |
| deploy batch | the workflow ends with `deployBatch` (it never deploys) | nothing until a person says `deploy <env>` (E5) |
| stopped / restarted | launch record without completion | E3: `orch.ps1 recover`, resume from the record |
| duel (`mode: 'duel'`) | two `devy` build the same question two ways (own worktrees, goals, evidence), `revy` compares them (kind plan), they debate (max 3 rounds, `revy` fact-checks) | E4: the owner judges from the debate record; the winner ships, the loser's branch closes (findings kept) |
| dispute | an agent disagrees with another's result (`board dispute`); the other answers once with evidence | agreed: nothing; still split after 2 rounds: E4 (both positions side by side) |

**Test-only flow** (/testy = `checky` lead -> `checky` test x N -> `checky` verify -> stronger retry -> `checky` lead (result
rule); deployed work on a test env, only its own target): `select` args -> Prepare (run.json,
tasks not live left out) -> per item test -> retest when > 25%
NOT_TESTED -> note audit -> ONE stronger retry (`models.retest`) of every check still NOT_TESTED -> verify every FAIL ->
finalize: all pass -> closed; own FAIL or incomplete -> failedTesting (back to the dev flow, E6); new defect -> one [Bug] per
ask (E6); PENDING -> app follow-up. Local env items: still NOT_TESTED -> ENV-FIX (E4) and a retest (`envFixCycles`, 2), then
held (`envFixOpen`), never failedTesting. Items the workflow could not publish -> `qa.ps1 finalize` (qa-kit L3;
`orch.ps1 recover`).

## Steps (you = the coordinator)
0. `orch.ps1 learn -Read -Skill orchestrate`. Project facts live in the brief / run.json / memory / the repo's CLAUDE.md.
1. **Scope:** group work by area (disjoint screens / packages per agent), not item count; the local env each repo uses.
2. **Brief:** `dev-kit/templates.md` "Wave brief" in the scratchpad (limits: "Writing standards", kinds `wave-brief`,
   `owner-message`) (bugs: `orch.ps1 bugbrief -Task <id> ...` per task).
3. **Launch** `/buildy` with `{ brief, agents:[{id, items, area, dependsOn?}], mode, kitDir, mandate, holdMerge? }`; then
   `orch.ps1 launch -RunId <id> -Script <path> -ArgsJson '<args>'` (the workflow records its exact args itself); then E1.
4. **Relay** (E8): decisions and contracts -> append to `<brief>.contracts.md`; never SendMessage a workflow agent (a hook
   blocks it).
5. **Close** (deploys only on a person's word, E5): reconcile backlog vs merged MRs; list only what is open, each with a reason.
- T1-T4 (test-only): `/testy { select: { statuses: ['promoted', 'inTest'], lists?, tasks?, exclude? }, target, kitDir,
  mandate }` (its Prepare agent builds the run: qa-kit L1 Selection; `target` = an env or a `qa.targets` group), or a ready
  `{ runDir, kitDir }` -> `launch` record -> E1. Its log lists the tasks left out (not live, no testing doc, no target).
~15 devy queue fine on the gate; beside app-lane QA cap `lanes` at 2.

## Events (check this table whenever something happens)
| # | Event | Action |
|---|---|---|
| E1 | You launched a workflow / agent, or a new session finds runs, and no heartbeat runs (a heartbeat dies with its session) | ONE heartbeat every 10 min: CronCreate `*/10 * * * *` (or `/loop 10m`), prompt: run `orch.ps1 supervise -AutoFix -Brief`, paste its output verbatim (one own line only when an ACT needs action), act on its flags; a second session's supervisor steps aside. Stop it when nothing runs |
| E2 | supervise prints ACT / WATCH / ❓ ASK | do the printed action (ASK: ask the owner once, record `supervise -App <name> -Answer <keep or close>`); leave healthy agents alone |
| E3 | Agents or a workflow stopped (crash, limits, a restart), or an agent handed off at its budget | `orch.ps1 recover`: per run its board, worktrees, MRs, decisions, a filled resume brief and the exact `Workflow({ scriptPath, resumeFromRunId, args })` (args the workflow recorded itself); resume refused -> the printed relaunch (`mode: 'resume'`); QA items never published -> its `qa.ps1 finalize` lines; never from scratch. You stopped it: `supervise -MarkStopped <run>` |
| E4 | DECISION <id> (supervise, the report's `decisions`; a dispute still split after 2 rounds or a duel's debate record: both positions side by side) · ENV-FIX <id> (a local-env fix only kitty or you may do; `envFixes`, `envFixOpen`) | DECISION: ask the owner with the options + recommendation (the owner judges a dispute or duel); `orch.ps1 decide answer -Id <id> -Answer '<their words>'`; several valid paths that evidence would settle -> you may start a /buildy `mode: 'duel'`. ENV-FIX: spawn `kitty` (kind env) with the request: it does the fix (local-env `up`/`refresh`/`drop`, shared DB repair) and answers `decide answer -Id <id> -By kitty -Answer 'done: <what>'` (or `'cannot: <why>'`); never ask the owner. The waiting item resumes. Held after the cycles: fix + `qa.ps1 retest` (a local item never goes to failedTesting for an env reason; no close path for NOT_TESTED) |
| E5 | A person says `deploy <env>` (`deploy.trigger: ask` only: supervise DEPLOY ASK -> ask ONCE per env, inside `deploy.minIntervalHours` say when) | at once, end to end, no question back: `orch.ps1 deploy plan -Env <env>` (every session's merged-not-deployed MRs), deploy per the org's deploy rules (`deploy merge` for a deploy branch), `deploy record -Env <env> -Mrs <refs> -By <who>`, `deploy intest -Apply` once live (supervise also does it). Never ask for or propose a deploy yourself |
| E6 | QA results: failedTesting tasks or new [Bug] tasks (supervise) | `orch.ps1 bugbrief -Task <id> -Agent B-<code> -Repos <r>` per task, then ONE /buildy `mode: 'bugfix'` for all (reproduce locally first) |
| E7 | A workflow finished (notification) | `launch -Done -RunId <id>`; `report -Run <id>` (never parse the notification); `next` (budget stop, batch, refusal) -> launch it; MR states from the report; open findings -> follow-up wave; `deployBatch` waits for a person's word (E5); then E10 |
| E8 | The owner changes a rule or scope mid-run | append it to the brief AND the contracts file (QA: `lead-notes.md`); agents re-read them before every push / check |
| E9 | The owner asks for something destructive while runs go on | do it yourself after they finish |
| E10 | A run finished (`retroDue`), supervise says "retro due", or signals piled up | /tidy once no other workflow of this session runs (one retro covers several runs) |
| E11 | HEAL: a guard block that was wrong, a script crash, a workaround, kit friction | spawn `kitty` (kind fix; K1-K3); it re-tests, gets a `revy` review, pushes and retires the lesson (`learn -Fixed`) |
| E12 | LEARN: something cost time, failed or surprised you | `orch.ps1 learn -Skill <s> -Kind <kind> -Text "<what + fix>"`; 2x -> a lesson (`-Lesson "(n×) ..."`); 3x -> a script check or default |
| E13 | SessionStart kit line (git state, gates, lint, ports, old layout, stopped runs, retro / audit due) | stopped runs -> E3 + E1; uncommitted -> commit + push; behind -> `git pull --rebase` once no agents run; old layout -> `orch.ps1 setup -Migrate` when nothing runs; audit due -> spawn ONE `kitty` (`subagent_type: 'kitty'`, kind audit); it pushes main itself: pull the live clone once no agents run, relay its ASK list |
| E14 | A new repo or stack joins | `dev.ps1 stack -Dir <module>`; wrong commands -> `.claude-stack.json`; conventions -> `rules/*.local.md` (README "Rule examples") |

## Change the kit (HEAL and extending)
- K1. Spawn ONE `kitty` (`subagent_type: 'kitty'`, kind build / fix / docs / audit / setup / env / recover) with the change or the
  friction in the owner's words. It works in its own kit worktree (never the live clone: runs execute it), keeps the kit generic
  (no org, product, tenant, host, id or local path; config through `kit.local.json`; org-only parts in the local overlay), adds
  parts with `kittool.py new` (README "Extending"), prefers a script check over a rule, and has `revy` (kind kit) review the diff.
- K2. Its checks (kitty step 8): `kittool.py lint` = 0 problems and 0 counted flow issues, `port` + `port --check`, parsed .ps1,
  `py_compile`, `node --check`, `tests/kit-tests.ps1`, `cost --steps` after a workflow change, `lint --org-terms`.
- K3. It commits (the pre-commit hook regenerates the README graph and the ports, and blocks on lint), rebases, pushes main
  fast-forward (pre-push blocks org terms and local files) and retires the lesson the change fixes (`learn -Fixed`). You pull the
  live clone once no run uses it and relay its ASK lines.

**Learn:** `orch.ps1 learn -Skill orchestrate -Kind <kind> -Text "<what + fix>"`.
