## Moved out of LESSONS.md (fixed in kit / historical / coordinator-only)
- (fixed in kit) A finalize re-run on an already-closed subtask overwrote its finalize.json record with an empty one (bug id lost, closed=false), so later steps saw an open task without a bug. The first run's record is now kept.
- (fixed in kit) finalize opened NO bug task for 10 confirmed failures and still closed the task: the run's list differed from the parent task's list, ClickUp refused the subtask, and the error went to 2>$null. finalize now retries without the parent (adds a 'Related' comment) and never closes a task whose failures have no bug task.
- My EvidenceName fix used .Replace() on report.ps1 and also changed Caption()'s regex (same prefix), adding a CAPTURING group that shifted $Matches[n]: the next finalize crashed on an empty caption (Substring). Fixed: the added group is non-capturing in both regexes, and Caption() falls back to the file name instead of throwing. When editing a regex, check every user of its group numbers; prefer (?:...) for new groups.
- (fixed in kit) A QA tester messaged the lead (wrong tenant login) but a workflow agent cannot be messaged back (SendMessage resumes a duplicate). test-and-close prompts now point testers at <runDir>/lead-notes.md, re-read before each check and when blocked; the lead answers there (and in the guide). Lead: write the answer to lead-notes.md, never SendMessage the tester.
- (fixed in kit) finalize warned that ALL evidence files of a run were badly named: the name check did not allow a hyphen inside the item code (`AB-CD-T13_01_x.json`) or a letter suffix on a check id (`T13b`). report.ps1 EvidenceName now allows both; lowercase slugs are still required.
- (fixed in kit) Bug-task titles grew each retest round ("... - failed checks X2, X3 - X1 — failed checks X4, X5"). finalize now drops everything from the first "failed checks" in the source task name before adding the new list.
- (fixed in kit) A re-run of finalize on an item kept open by a NOT_TESTED check raised a SECOND bug task, posted a second results comment, and (its Google Doc create failed) overwrote the report link with an empty one. finalize now treats a subtask already in finalize.json as published (reuses its bug, only re-checks whether it can close) and keeps the previous report when the doc create fails.
- (fixed in kit) Two test-and-close workers mapped their first app item to lane 1 and leased it under the same id, so both "owned" the phone (the board CLAIM caught it). Phone leases are now per worker (`qa-<instance>-<lane>`), so the second waits in the fair queue, and extra workers start on lane (instance-1).
- (fixed in kit) A web item finished with device checks PENDING and the run ended with them untested until the lead added an app item by hand. The workflow now appends an app follow-up `<code>A` (only = the PENDING checks) to run.json and runs it on the phones in the same run.
- (fixed in kit) `skipClose` items saved nothing to disk (verdicts only in the workflow's return value) and never got a finalize.json, so the supervisor kept their run "unfinished" and held its bug batch. They now write `<code>/results.json` + `held.json`, which supervise and qa-seat treat as finished. Items that share one task don't need skipClose: finalize already keeps the task open until all of them are published.
- (fixed in kit) Short-form `/test-and-close { runDir }`: the small load-run agent sometimes returned run.json without `items[]`, so workers died at start. The loader now validates items[] and retries once on a stronger model; if it still fails, pass the full run.json object as args.
- (fixed in kit) Reviewers could not tell what a FAIL screenshot was about: `annotate.ps1` (box / arrow / label on any screenshot, one call) and `ui.ps1 shotmark` (screenshot + box on elements by text / #id) now exist. Mark every FAIL screenshot.
- (fixed in kit) finalize warned on valid files (pdf/csv exports, `_verify_` without nn) and skipped evidence saved outside shots\/evidence\ or given as absolute paths: finalize now collects listed evidence from anywhere under the run dir and drops helper scripts.
- Small/cheap close agents sometimes refuse to publish; that's why `autoclose.ps1` exists — always start it for a run.
- Keep web agents to ≤ 2 Chrome ports; killSession() when done — other sessions run Maven/Angular builds.
- A "Enable notifications" toast can cover the header's right side; browser.mjs grants the permission so it doesn't appear.
- (fixed in kit) api.ps1 crashed on a binary response (image/file download) and, called from Git Bash, a /api/... path arrived as C:/Program Files/Git/api/... (MSYS path conversion). Binary bodies are saved next to the evidence as <Save>.body.<ext> with a text stub in the JSON; MSYS-mangled paths are restored.
- (fixed in kit) A run launched with args.skipClose still closed its task (skipClose was read per item only), and finalize closed a task that had NOT_TESTED checks (a dependency was not deployed). Run-level skipClose now applies to every item; finalize keeps a task with NOT_TESTED checks open and comments why (run.json tracker.closeWithNotTested overrides).

## Original wording of lessons condensed into LESSONS.md
- (2×) Silent 200-with-empty-data bugs (a batch call returning rowCount 0) and 5xx dismissed as "just restart it" both need proof: save the failing request/response and check the observability tool before calling it infra; an unverified 5xx is FAIL.
- (2×) Screenshot/canvas-capture checks: time them per screen (a light screen took 5 s, a long list 77-128 s against a 30 s tool timeout) and don't blame host CPU without a re-run at low load. A guide scenario for a screen that does not host the component must be reported, not silently moved to another screen.
- (2×) LLM-driven checks (an AI decider/assistant) are intermittent (one check approved without confirmation in ~6 of 14 runs): run each such check 5-14 times and record every run; keep the first and each deviating run as evidence.
- (2×) Items skipped in a run showed up in the outcome with no reason: write the skip reason into run.json so the learn step can tell why.
- (3×) Setup evidence named like `<code>-SETUP_02` is flagged as off-standard by finalize (harmless, still published): name setup evidence `<code>-<nn>-<slug>`, and never list source files or folders as evidence.
- (3×) Layout fixes (scroll, max-height, a popped-out panel's drag boundary, a search field) pass at 1920x1000 but fail at 1366x768: test both viewports and measure header/panel bottoms vs innerHeight with real wheel scrolling only (scrollIntoView hides overflow:hidden clipping).
- (3×) Guide data drifts on shared test environments (records completed, deleted or renamed by others): make your own data through the API and record it; guides need a "Set up first" block.
- (2×) Parallel items toggling a shared tenant setting cause transient 403s in other items: serialise those checks or record the setting state with the evidence.
- (2×) The swarm's APK can be days old: compare the APK's commit with the branch head and rebuild with `android-swarm/app-build.ps1` before any app retest.
- (11×) Retests of a dev fix often fail on the sibling path (the single GET fixed but the list GET still 500; a 400 turned into a 500 on another state; import fixed but the edit round-trip not; i18n keys still missing on the third round: diff all keys against the default locale). Dev briefs and testers exercise the full reported flow end to end (create/import, edit, cancel on approved/invoiced states), not only the original error.
- A retest check whose fix was merged but not deployed (a service) came back PASS_WITH_NOTE although the tester's own text said it could not be verified, and finalize closed the bug. Undeployed fix = NOT_TESTED, never PASS_WITH_NOTE; the note audit should reclassify such checks.
- (fixed in kit) `pwsh -File deployed.ps1 -Mrs 'a!1','b!2'` reported BAD-REF for every MR: -File passes the quotes literally. deployed.ps1 now strips quotes and splits on commas/spaces. Also: a consumer can reach a test environment through an automated release while its producer is still undeployed - before testing, run deployed.ps1 for EVERY repo of the task, not just the one you expect to be live.
- A server-side config check (model, temperature, fallback) is NOT_TESTED from the API lane and keeps the task open after every bug on it is fixed. Close it by verifying the config in the deployed code plus its unit tests (run the repo validation script directly when pytest is not in the linked venv), say which env overrides could not be seen, then close.
- (fixed in kit) deployed.ps1 said NOT-DEPLOYED for MRs that were live: the deploy branch got main through a squashed "merge main into staging" commit, so the MR merge commits were not ancestors. It now also accepts "MR on its target branch + its files identical on the deploy ref". A manual server deploy (no branch update) still reads NOT-DEPLOYED: trust the owner and say so in the run context.
- (27×) Evidence hygiene: finalize warns on off-standard names (CODE-ID_NN_slug) and on files listed in results.json but missing (helper .mjs scripts, absolute paths). Save evidence into the item folder with the standard name, list only files that exist (never folders), relative names.
- (2×) The test web app can be redeployed mid-run: re-check the bundle version/timestamp before finalising FAILs and re-run them on the new build.
- (25×) Testers hid real defects in PASS_WITH_NOTE / findings. Any 5xx, stuck flow or unsaved data is FAIL — the note audit will reclassify it anyway, so report it right the first time.
- Test environments often run an older build than the target branch. Before a FAIL, check the change is deployed (endpoint exists, web bundle contains the change); otherwise NOT_TESTED "not deployed yet".
- Guides go stale when later packages change screens; test the same intent on the current screen and say so (PASS_WITH_NOTE), not FAIL.
- Component-library dropdown menus that open on HOVER (e.g. ng-zorro `nz-dropdown`) need `hoverSel(page, selector)`; menu items render in an overlay container (`.cdk-overlay-container`), not under the trigger. Row "…" menus are `.anticon-more` in the row; menu items `.cdk-overlay-container li`.
- ng-zorro selects: options are `.ant-select-dropdown:not(.ant-select-dropdown-hidden) .ant-select-item-option`. Column filters: `th .ant-table-filter-trigger`, then `.cdk-overlay-container input`.
- Some web deploys are two-stage: merging to the target branch deploys nothing; a release pipeline (often a scheduled one run on demand) copies it to a deploy branch, and THAT branch's pipeline puts it on the test site. Wait for the second pipeline (`deployed.ps1` reports "no successful <deploy job> includes it yet" until then).
- A test environment's JWT signing key can differ from the one in the repo's config: forged/re-signed tokens get 401 there, so prove "the API refuses a token for another product" by unit test or with the deployed key. A separately deployed service (e.g. a cloud function) may be undeployed: check before testing.
- Use a secondary test user for per-user preference checks, and keep one tenant/account with the feature OFF for "nothing else changed" (R) checks; never change its settings.

## Moved by learn.ps1 (-Fixed / -Trim), oldest first
- (fixed in kit) (2×) The swarm's APK can be days old: compare its commit with the branch head and rebuild with `android-swarm/app-build.ps1` before any app retest.
- (fixed in kit) (3×) LLM-driven checks (an AI decider/assistant) are intermittent: run each 5-14 times, record every run, keep the first and each deviating run as evidence. Re-run a deviating run before FAIL, and log its timestamp.
- (fixed in kit) (3×) After a backend-service restart or redeploy the first assistant turns can answer 'data connection timed out' (tool-search calls only) for a few minutes: run a warm-up chat turn and re-run the check before any FAIL or bug is opened.
- (fixed in kit) (8×) Pre-run prerequisites: before the run the lead checks every precondition the guide needs on the target tenant/role: feature flags and settings (current value, who switches and restores them; ask the owner when one was turned off on purpose), and the test data and accounts the steps need (a driver with a stocked van, franchise data, a soft-delete column, a role with the right authority); it writes each into lead-notes.md. Missing data the API can create is created up front; a missing account or schema the lead cannot supply is marked NOT_TESTED in run.json before testers start, with the missing thing named. An environment-level gate the tester cannot switch (server config, disallowed tool) is NOT_TESTED with the setting named, never FAIL.
- (fixed in kit) (30×) Evidence hygiene: name evidence per evidence-standard.md (`CODE-checkId_NN_slug`, marked copy `-marked`, setup `<code>-<nn>-<slug>`), relative names only, and never list folders or helper scripts. Run `finalize.ps1 -Check` before you publish: it blocks on listed files that are missing and lists off-standard names. Rename those before publishing.
- (fixed in kit) (28×) Defects are never notes: any 5xx, unexpected 4xx, stuck flow or unsaved data is FAIL (the note audit reclassifies it anyway). Silent 200-with-empty-data and a 5xx "fixed by a restart" need the saved request/response and an observability check; an unverified 5xx is FAIL. This includes a wrong answer stated as fact with HTTP 200 and no tool error (LLM checks: compare with the DB), a downstream 5xx surfacing only in a finding, and errors in the first turns after a restart.
- (fixed in kit) (12×) Retests of a dev fix fail on the sibling path (list GET still 500, another state, edit round-trip, i18n keys: diff all keys against the default locale): exercise the full reported flow end to end (create/import, edit, cancel in locked/terminal states), not only the original error. Also run a second shift on the same calendar day after an after-midnight End of Day (same-day inspection rule lets the previous shift satisfy the new one).
- (fixed in kit) (3×) LLM count questions: before testing, compute every plausible definition of the entity in the DB truth (flags, types, active/deleted). Run 6+ fresh sessions. If the number changes between sessions and each number matches some definition, that is a FAIL (definition drift), not data drift.
- (fixed in kit) (6×) A user-facing failure in the first turns after a restart or redeploy is its own X check (FAIL with timestamps and time since restart), not a reason to discount the run; count the guide's runs only after the warm-up turn. A clean later run never refutes it: a verifier or retest that did not recreate the idle/restart window is inconclusive, and the FAIL stays. Readiness = the listener/health endpoint answering, not the first startup log line.
- (fixed in kit) (3×) Phone leases: keep the lease through waits under ~30 min (re-acquire queues ~20 min behind the RAM gate); don't start gated tests while waiting for a phone.
- (fixed in kit) (2x) Before a retest that checks new search or index fields on a tenant, confirm the tenant index was rebuilt (reindex): missing fields give 0 results and NOT_TESTED, not FAIL. Compare each search result with the unsearched list for exact counts.
- (fixed in kit) (3×) Shift/day-boundary retests: start a second shift on the same calendar day after an after-midnight end of day (a same-day rule let the previous shift's record satisfy the new one), and check every screen and gate that reads the rule, not just the one in the bug (a fix to the gate left the screen loader on the old rule, so the flow got stuck).
- (fixed in kit) (3×) Intermittent server failures in a tester's evidence (503/502, a timeout, a stall, a cold start): before refuting or confirming, the verifier reads the server logs or observability for the first tester's UTC window (worker auto-restart, cold start, deploy restart) and quotes what it finds. A cause found there keeps the FAIL (or makes it inconclusive with the cause named); a clean re-run on a warm server never refutes it (CPR X1 gunicorn worker recycle, HMAPI-RR X4, HMWEB-RR X6).
- (fixed in kit) (3×) Before a run relies on an MCP server (<local DB MCP>, <other MCP>), confirm it connected; a failed connection is noted in the run log, not treated as a missing capability.
- (fixed in kit) (3×) Name evidence files to the finalize standard at capture time and confirm each file a check points to exists before the -Check run; -FixNames renames are friction (GRP missing shot, GRPR two renamed X2v files). GRPS-X3: a 0-byte unsupported .body.bin made -FixNames exit 1; check each cited file's type and size before renaming.
- (fixed in kit) (2×) Popovers and heavy modals (date-filter popovers, a modal with a render-error flood): browser.mjs now caps clickText at 15 s (boundingBox fallback) and settle at 8 s (stops on an error flood); if a click still misses, click the boundingBox with page.mouse.click.
- (fixed in kit) (10×) <sql MCP>, <local DB MCP> and <other MCP> MCPs fail to connect or drop mid-run: check availability at run start, note their status in the run log, and run replica SQL through the <sql MCP> venv db_mcp._query or the kit sql.py helper instead of marking checks NOT_TESTED for that reason alone. (<other MCP> too; the 2026-10-14 HG/IMP runs hit it again).
- (fixed in kit) (4×) Name evidence files to the standard at capture time and check each results.json reference exists before finalize -Check -FixNames: FixNames renames files and rewrites results.json on disk, and a missing or 0-byte file fails the check. If a listed file is missing, do not silently drop it from results.json: capture it or record the gap in the run log (RAPP X5 nr-after dropped, 2026-10-15).
- (fixed in kit) (4×) Every NOT_TESTED check gets its cause in the run log (APPLY not run, search index not reindexed, phone-only, undeployed fix); fix the cause before the run or mark a deliberate skip, since finalize keeps the subtask open until it clears.
- (fixed in kit) (1×) The test tenant's ROLE_ADMIN has Daily Activity Summaries / EOD Surveys / Inspections / Driver Breaks screens OFF in role_settings, so deep links silently redirect home: query role_settings before planning UI checks and name the switch in the guide.
