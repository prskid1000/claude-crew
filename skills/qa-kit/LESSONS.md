# QA lessons — active rules (read before testing; ≤ 40 lines)
Newest first, one line each, `(n×)` = times seen. Fixed/old entries live in `HISTORY.md` (never read it for work).
UI gotchas for one product go under `## Project: <name> (target <target>)` (selectors, accounts to use or never touch, app login
steps) — never passwords; those live only in `targets.local.json`.

## General
- (3×) Name evidence files to the standard at capture time and check each results.json reference exists before finalize -Check -FixNames: FixNames renames files and rewrites results.json on disk, and a missing or 0-byte file fails the check.
- (4×) Every NOT_TESTED check gets its cause in the run log (APPLY not run, search index not reindexed, phone-only, undeployed fix); fix the cause before the run or mark a deliberate skip, since finalize keeps the subtask open until it clears.
- (9×) <sql MCP>, <local DB MCP> and <other MCP> MCPs fail to connect or drop mid-run: check availability at run start, note their status in the run log, and run replica SQL through the <sql MCP> venv db_mcp._query or the kit sql.py helper instead of marking checks NOT_TESTED for that reason alone. (<other MCP> too; the 2026-10-14 HG/IMP runs hit it again).
- (2×) A FAIL found during a retest is blamed on the MR under test only after checking the build from before that MR (old build, or git blame/log on the failing line); otherwise the bug task says 'pre-existing, not caused by <MR>' with that evidence (GRPR X2: the runIds.forEach TypeError predates <repo>!6284; APPL X2 'nullnull' phone called pre-existing without proof).
- (3×) A retest of a fix in shared code (a rule, a modal, a gate) exercises every caller and every screen that reads the same code path or stored record (EODR X3 home step cards, GRP modal opened from each caller, APPX4 gate's target screen), not only the reported screen.
- (2×) Flags switched on for a retest (e.g. a tenant feature flag) are restored to their default at teardown and noted in lead-notes.md; the next run starts from the documented state, not from the last run's leftovers.
- (2×) finalize reports closed False when the item (or a sibling item of the same task) has a NOT_TESTED check, a FAIL without a bug task, a PENDING check, or a sibling item not finalized yet (finalize.json keptOpen / waitingFor says which); FAILs with a bug task close the task (the failed part moves to the bug). The subtask stays open by design until those clear. Say so in the run report (open by design, not a stuck close); do not re-close it by hand.
- (3×) Lanes that share one admin user share the assistant chat list: give each lane its own session key, expect foreign files there, and delete only your own.
- (4×) Lead notes can widen scope mid-run: re-read lead-notes.md before each check and before releasing a seat; log added checks, never edit the guide in place. A check the lead requires (e.g. a regression on another product that shares the changed code) goes into the run item (its own item, or `add-retest.ps1 -Only <ids>` plus the check in the guide), never only into lead-notes.md: retest items run only their -Only ids and skip lead-note-only checks silently.
- Deployed? Before any FAIL run `deployed.ps1` for EVERY repo of the task (a consumer can be live while its producer is not). Undeployed fix = NOT_TESTED, never PASS_WITH_NOTE. A manual server deploy still reads NOT-DEPLOYED: trust the owner and say so. Two-stage web deploys (release pipeline to a deploy branch) go live only after the second pipeline. The test app can be redeployed mid-run: re-check the bundle version before finalising FAILs. A manual deploy the owner confirms counts as live: check it via an API marker (new field, version endpoint) before holding checks as NOT_TESTED. (8×)
- (3×) Layout fixes (scroll, max-height, panel drag bounds, a search field): test the smallest and largest supported viewports (e.g. 1366x768 and 1920x1080), measure header/panel bottoms vs innerHeight with real wheel scrolling only (scrollIntoView hides overflow:hidden clipping).
- (6×) Guide data drifts on shared environments (records completed, deleted, renamed): create your own data through the API and record it. Guides go stale when later work changes a screen: test the same intent on the current screen and say so (PASS_WITH_NOTE), not FAIL. When the guide's Expected disagrees with the screen on a design detail (button layout, breakdown per period), read the MR/code first and quote both readings; if the code does not settle it, ask the lead before the run closes (SKILL step 5 (c)); never close a check as 'possible guide mismatch, owner to decide'.
- (2×) Parallel items toggling a shared tenant setting cause transient 403s elsewhere: serialise those checks or record the setting state. Per-user preference checks use a secondary test user; keep one tenant/account with the feature OFF for "nothing else changed" (R) checks and never change it.
- (6×) Screenshot/canvas-capture checks: time them per screen (a long list took 77-128 s vs a 30 s tool timeout); don't blame host CPU without a re-run at low load. A guide scenario for a screen that does not host the component is reported, not silently moved. Wait until the table has pageSize rows before timing (lazy rows render late). A capture that blocks the page past its cap is FAIL, with the profile saved. Compare each captured picture with a live page shot on every page type the feature runs on (dashboard/home, list, record, map); for an uploaded capture download it (chat files download API) and diff it against the page; a page type the guide has no reference picture for gets its own X check.
- (2×) Skipping an item: write the skip reason into run.json so the learn step can tell why.
- A server-side config check (model, temperature, fallback) is NOT_TESTED from the API lane: verify it in the deployed code plus its unit tests (run the repo's validation script directly when pytest isn't in the linked venv), name the env overrides you could not see, then close.
- A test environment's JWT signing key can differ from the repo config (re-signed tokens get 401): prove "refuses a token for another product" (several products sharing one auth service) by unit test or with the deployed key. A separately deployed service (e.g. a cloud function) may be undeployed: check first.
- Component-library overlays (e.g. ng-zorro): hover-open dropdowns need `hoverSel(page, selector)`; menu items render in `.cdk-overlay-container` (row "…" menus `.anticon-more`, items `.cdk-overlay-container li`); select options `.ant-select-dropdown:not(.ant-select-dropdown-hidden) .ant-select-item-option`; column filters `th .ant-table-filter-trigger` then `.cdk-overlay-container input`. date-range pickers ignore typed text + Enter (no ngModelChange): click td.ant-picker-cell-in-view[title='dd/MM/yyyy'] and use the header prev/next buttons; nz-select options are virtual-scrolled (scroll the overlay list); paginate with li.ant-pagination-item[title=N] a and wait for the first row's id to change. (2×)

## Project: <feature> app (app lanes)
- (1×) Finishing / On-site screens never go idle in a release build (Time On Site timer), so `ui.ps1 dump` fails there: use shot + tapxy. The camera shutter moves from y~2665 to ~2424 after the first thumbnail appears (APPQ-X1).
- Timeout or 'saved then network lost' checks: set the emulator http_proxy to 10.0.2.2:<port> on a small host CONNECT proxy with delay/block controls; wait for the delayed response before judging, and clear the proxy (:0) afterwards. Use a TLS-record-aware proxy (LOADR/scripts/saveproxy.mjs): a plain delay proxy cuts the save's ClientHello. (2×)
- (2×) A <feature>-copy does not copy tracking numbers: add them with PUT /api/<feature>-orders/{id}/goods-info, then log in to the app again. Scan type and scan location are not in the loader GET: verify them in the tenant DB (feature_goods_info) or the report API.
- (3×) Lane driver already owns today's IN_PROGRESS run, so assigning a leg fails with 'driver already assigned to another run': <feature>-copy the order, POST /api/sale-orders/mark-as-approved?ids=, POST /api/<feature>-runs/move-orders {toRunId:<lane run>,fromRunId,orderIds}, then POST /api/legs/communicate. On a same-day copy, pick a driver with no run that day or copy to the next day; resourcing fails otherwise.
